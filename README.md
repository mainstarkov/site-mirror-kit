# Site Mirror Kit

Библиотека Node.js и команда для сохранения доступной браузеру части сайта и просмотра копии на localhost. Работает на компьютере пользователя через Chromium, без облачного сервиса и API-ключей.

**Это архив клиентской части, а не восстановление исходного проекта.** Сохраняются полученные HTML, CSS, JavaScript, изображения, шрифты и ответы GET-запросов. Серверный код, базы данных и исходники до сборки недоступны. Полная копия любого сайта «один в один со всеми функциями» не гарантируется.

## Установка

Нужен Node.js 22 или новее:

```sh
git clone https://github.com/mainstarkov/site-mirror-kit.git
cd site-mirror-kit
npm ci
npm run setup
npm link
```

Chromium устанавливается через [Playwright](https://playwright.dev/docs/browsers). Вместо него можно выбрать установленный Chrome: `--channel chrome`.

## Сохранить и открыть

```sh
site-mirror capture "https://example.com/" --out captures/example --serve
```

Терминал покажет путь к архиву и ссылку локальной копии. Откройте её в браузере. Сервер останавливается через Ctrl+C.

Повторный запуск сохранённой копии не требует исходного сайта:

```sh
site-mirror serve captures/example
```

Обход нескольких страниц того же домена:

```sh
site-mirror capture "https://example.com/" --out captures/example-pages --pages 10 --wait 2500 --serve
```

- `--pages`: максимум страниц, по умолчанию 1, допустимо 1–100. Переходы собираются из ссылок `<a href>`, фрагменты не образуют отдельные страницы.
- `--wait`: время ожидания после ограниченной прокрутки, в миллисекундах; по умолчанию 1500, максимум 30000.
- `--out`: новая папка архива. Существующая папка никогда не перезаписывается.
- `--port`: порт локального сервера, по умолчанию 4173.
- `--channel chrome`: использовать установленный Google Chrome.
- `--serve`: после сохранения запустить локальный сервер.

В архиве:

```text
manifest.json    URL → файл, статусы, список страниц и ошибок
files/           полученные файлы, с хешами URL в именах
snapshots/       HTML после выполнения JavaScript, для просмотра и анализа
```

Локальный сервер воспроизводит исходные HTML-ответы и скрипты. Снимки DOM лежат отдельно: повторное выполнение скриптов поверх готового DOM часто ломает приложения. Файлы в `files/` сохраняются без изменения; ссылки переписываются во время локальной выдачи. Для передачи архива другому человеку достаточно передать всю папку и запустить её этой библиотекой. Открытие HTML двойным щелчком не заменяет сервер.

## Как библиотека

```js
import { capture, serve } from 'site-mirror-kit';

const result = await capture('https://example.com/', './captures/example', {
  maxPages: 3,
  waitMs: 1500,
  onProgress: console.log,
});
console.log(result.manifest.errors);
const { server, url } = await serve(result.directory, { port: 4173 });
console.log(url);
// Когда закончите: server.close();
```

Локальное подключение в другой проект: `npm install /path/to/site-mirror-kit`. Публикации в npm пока нет.

## Границы работы

- Сохраняются только ресурсы, реально запрошенные при загрузке и прокрутке посещённых страниц. Не нажимаются меню, кнопки и формы. Ресурсы за такими действиями могут отсутствовать.
- Локальные кнопки, стили и скрипты могут работать. Авторизация, оплата, отправка форм, WebSocket и изменение серверных данных не воспроизводятся. POST/PUT/DELETE блокируются уже при записи.
- Записанные GET-ответы API воспроизводятся как снимок данных. Новые запросы, которых нет в архиве, получают 404; сервер не пересылает их исходному сайту.
- Абсолютные и обычные относительные ссылки переписываются для localhost. Вычисляемые адреса, экранированные URL внутри JavaScript, нестандартная кодировка, сложные SPA, проверки домена, service workers, DRM, бесконечная прокрутка и видео могут не воспроизводиться. Текст предполагается UTF-8.
- При локальном воспроизведении CSP ограничивает ресурсы текущим сервером, блокирует формы и workers. Это меняет поведение некоторых сайтов. Обычные переходы страницы не являются изолированной песочницей.
- Ограничение: 100 МБ на ответ, 500 МБ на архив. Тело ответа сначала читается браузером в память; для больших медиа нужен потоковый загрузчик. В `manifest.json` отражаются ошибки записи, но отсутствие ошибки не доказывает полноту копии.
- Используется новый браузерный профиль без пользовательских cookies; обход CAPTCHA, доступа по паролю и защиты от ботов не предусмотрен. Не переносите в него секреты. Архив может содержать данные и URL из публичных API — проверьте их перед публикацией.
- Сервер слушает только `127.0.0.1`. Сохранённый JavaScript выполняется в браузере: открывайте только доверенные архивы. Используйте инструмент для своих сайтов или с разрешения владельца.

## Проверка

```sh
npm test
```

Интеграционная проверка создаёт два тестовых сервера, записывает страницы и выключает оба источника. После этого настоящий браузер проверяет локальные стили, внешнюю картинку, JSON, кнопку, переходы, редирект, 404/405 и защиту от выхода за папку архива. Это проверка на контролируемом сайте, не обещание совместимости со всеми сайтами.
